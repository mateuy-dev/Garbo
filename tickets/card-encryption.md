## Objective

Protect sensitive cards (national ids, passports...) with encryption, while the vault stays a plain folder synced by an external tool (e.g. Dropbox). Define it with OpenSpec on this ticket's branch (`/opsx:propose card-encryption`), building on the vault format from `vault-and-cards`.

Decisions taken (exploration session, 2026-10-23):

- **Only sensitive cards are encrypted** (a card can be marked sensitive; id-like types are sensitive by default). Rejected: encrypting everything (the shopping card shouldn't need a password) and encrypting single fields inside a file.
- **Visible shell**: a sensitive card keeps `card.yaml` in plain text with name, type and owner, so the list shows and filters it without the password. Code, number, dates and notes go to `secret.yaml.enc` in the same card folder, and photos become `front.jpg.enc` / `back.jpg.enc`. Accepted leak: whoever opens the folder sees e.g. "DNI · Maria". Rejected: encrypting the whole card (owner and title invisible without the password). Marking/unmarking moves fields between the two files and encrypts/decrypts the photos. Decrypted content is never written to disk.
- **Keys**:
  - password --Argon2id--> unwraps a **random user key**, stored wrapped in `.garbo/user-key.yaml` (kdf params, salt, nonce, wrapped). A wrong password fails the AEAD tag, so no separate check field. Changing the password rewrites only this file.
  - **one random symmetric key per owner folder**, wrapped by the user key, **one file per key** in `.garbo/keys/<keyId>.yaml` (label, nonce, wrapped). Key files are never modified after creation, so sync can't conflict on them. Rejected: a single `keyring.yaml` (two devices importing keys at once would conflict). Rejected: a key pair per owner (adds nothing).
  - `owner.yaml` holds **no key material**, only its `keyId`. Owner folders can be shared (see `owner-key-sharing`), so the wrapped keys live in each user's own `.garbo/`, which is not shared.
  - Moving a card between owners with different keys re-encrypts its files, transparently.
  - Suggested cipher: XChaCha20-Poly1305 (or AES-256-GCM); pick a multiplatform crypto library in the design.
- **Unlock**: the password once per session; on each device the user key is cached in Keychain/Keystore behind biometrics. Device state (biometrics on, last unlock) stays on the device, never in the folder.
- **Recovery code**: optional. Offered when the vault's encryption is set up, skippable with a clear warning ("if you forget your password you lose your sensitive cards"). Generated by Garbo (~120 bits, readable groups without confusable characters, e.g. `K7QF-M2XA-9RDT-WH4C-P6NE-J3VB`), shown once, copied/printed; the user retypes two groups to confirm. Stored only as a second wrapper of the user key in `.garbo/recovery-key.yaml`. Flows: forgot password (code -> new password -> suggest a new code), regenerate (unlocked), disable (delete the file).
- **Password reset from a device that holds the user key behind biometrics** is allowed, without the recovery code.

Out of scope: sharing owner keys (`owner-key-sharing`), key rotation/revocation (later; `keyId` already allows it), public-key sharing.
